# x402

[Official documentation](https://docs.x402.org/introduction) · [Specification repository](https://github.com/x402-foundation/x402) · [HTTP payment headers](https://docs.x402.org/core-concepts/http-402)

x402 is an open payment protocol built around HTTP 402 Payment Required. It lets resource servers advertise machine-readable payment requirements and lets clients authorize a compatible payment when their policy allows it.

## The version 2 exchange

A typical interaction proceeds as follows:

1. The client requests a paid resource.
2. The server returns 402 with a base64-encoded `PaymentRequired` object in `PAYMENT-REQUIRED`.
3. The client evaluates the offer and retries with a `PaymentPayload` in `PAYMENT-SIGNATURE`.
4. The server verifies the payload, fulfills the request, and handles settlement according to the selected scheme.
5. `PAYMENT-RESPONSE` reports the settlement result.

For example, a research agent can request a paid dataset endpoint and evaluate its advertised asset, network, destination, and price before authorizing access. This is a conceptual example, not a payment request.

Clients and servers must support the selected scheme and network. A facilitator can assist verification and settlement; it is not the source of the user's spending authority.

Authorization and settlement are distinct, especially for schemes that defer settlement. Preserve operation identities and receipts, and reconcile uncertain outcomes before paying again.

x402 does not provide a complete procurement policy, wallet-custody system, refund workflow, or cumulative agent budget.
