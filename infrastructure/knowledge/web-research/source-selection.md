# Research source selection

Source selection determines which materials are suitable evidence for a claim. Evaluate authority, directness, recency, independence, scope, and whether the content actually supports the proposed conclusion. Search ranking is a discovery signal, not an evidence-quality score.

Choose authority according to the question. A specification defines a protocol; an implementation's source establishes what its code does; a controlled experiment measures behavior under stated conditions. A vendor benchmark can be useful without establishing performance on another application's workload.

For “Does this SDK support streaming?”, prefer the documentation and release notes for the installed version, then inspect the implementation if the contract remains unclear. An older tutorial can demonstrate a former API while being unsuitable installation guidance today.

Check publication date separately from the date of the event or measurement. For research papers, inspect corrections and retractions where available; [Crossref's Crossmark](https://www.crossref.org/services/crossmark/) describes publisher-supplied updates to the scholarly record.

Independent support matters more than repetition. Several articles copying one announcement still provide one underlying source. Follow citations back to their origin, preserve disagreements, and distinguish a documented guarantee from an observed result or your own inference. If the evidence does not resolve the claim, retain that uncertainty rather than selecting whichever source sounds most confident.
