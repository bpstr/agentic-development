# DeepSeek open-weight models

[DeepSeek-V4.1-Flash model card](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash) · [DeepSeek API changelog](https://api-docs.deepseek.com/updates/) · [Canonical DeepSeek-R1 repository](https://github.com/deepseek-ai/DeepSeek-R1)

**DeepSeek-V4.1-Flash**, released September 10, 2026, is the current downloadable example of DeepSeek's newer architecture family. The publisher describes it as a natively multimodal model with visual understanding and exposes the hosted version through the `deepseek-flash` alias. The official Hugging Face artifact is MIT-licensed and provides model configuration plus serving guidance. Use the exact artifact revision and runtime rather than treating the hosted alias and downloadable checkpoint as interchangeable deployments.

The model is a large mixture-of-experts system. Sparse activation can reduce computation per token, but it does not make the complete checkpoint or its runtime state equivalent to the number of active parameters. Plan storage, accelerator memory, interconnect, quantization, and cache requirements from the actual files and supported serving runtime. The publisher's model card currently documents Transformers and vLLM integration; pin compatible versions because large-model architecture support changes quickly.

On the hosted API, the previous `deepseek-v4-flash` and `deepseek-v4-flash-vision-exp` names are retired and temporarily route to V4.1-Flash for compatibility. Do not make those compatibility aliases a new long-lived application contract. The September 10 changelog also clarifies that **DeepSeek V4 Pro continues to be served after September 14, 2026 with its billing method unchanged**, superseding the earlier phase-out language in the launch announcement.

DeepSeek-R1 remains an important earlier reasoning-model release and includes smaller distilled checkpoints. Distillation trains another model from generated examples or other teacher signals; a distilled checkpoint is a separate deployment artifact with its own base architecture, tokenizer, capabilities, and provenance. It should not inherit the full model's benchmark results or deployment requirements by association.

For evaluation, reproduce the relevant prompt template, processor, sampling and reasoning settings, generation budget, tool parser, and multimodal path. Record the complete model identifier or checkpoint revision, runtime, precision or quantization, and serving configuration. Open weights make independent deployment possible; they do not make local, quantized, third-party-hosted, and first-party API configurations behaviorally equivalent.
